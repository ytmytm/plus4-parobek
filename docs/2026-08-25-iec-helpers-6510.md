# IEC Helpers and 6510 SJL Receive Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Share IEC `M-` upload/exec helpers on the stock-1541 serial and SpeedDOS paths, and add a Hackjunk type-1 6510 SJL receive loop selected from the lowmem trampoline.

**Architecture:** Detect `cpu_port_type` once at install (siziolib values). Type 0 keeps the current `BIT $01` JD loop. Type 1 uses a second cycle-padded loop (DATA in bit 0, CLK in bit 5) via a trampoline `JMP`. Type 2/3 skip SJL and 1541 SERIAL. `iec_m_minus` / `iec_mw_one_chunk` / `iec_me` replace duplicated LISTEN/`M-` sequences.

**Tech Stack:** ACME 6502, GNU make, Python contract tests, VICE `xplus4` for type 0.

## Global Constraints

- Spec: `docs/2026-08-25-iec-helpers-6510-design.md`
- IEC order unchanged: burst → SD2IEC SJL → parallel → drive-JD SJL / host-JD ROM → 1541 SERIAL → ROM
- `UI` at most once per LOAD (`iec_note_drive_class` only)
- `cpu_port_type`: 0=8501, 1=6510+patched KERNAL, 2=6510+stock KERNAL, 3=unknown
- Type 1: never `$00=$1F`; restore `$00=$0E`; do not `ORA #$08`; skip datasette bit-3 gate
- Type 2/3: no `SJL_load` / `fast1541iec_load`
- Do not merge SJL bitbang with `ROM_TALK`; do not change drivecode; do not table-drive `iec_load`
- Stay under `$C000`. Branch: `feature-fast1541iec`

- [ ] **Step 2: Create `src/cpu-port-detect.asm`**

Port siziolib `detect_cpu_port_type` (save/restore `$01`; do not leave the port wedged):

```asm
; Sets cpu_port_type in the RAM trampoline. Clobbers A/X.
; 0 = 7501/8501: DATA-out bit0 follows DATA-in bit7; bit5 reads 0
; 1 = 6510, $F30C DDR init ≠ $0F (Hackjunk patched)
; 2 = 6510, $F30C == $0F (stock KERNAL)
; 3 = unknown
KERNAL_CPU_DIR_INIT = $f30c

detect_cpu_port_type:
	lda #0
	sta cpu_port_type
	lda $01
	pha
	; Try 8501: drive DATA-out low (clear bit 0), require bit 7 follow
	and #%11111110
	sta $01
	lda $01
	and #%10000000
	bne .not_8501		; bit7 still high while bit0 low → not 8501 DATA pair
	lda $01
	ora #%00000001
	sta $01
	lda $01
	and #%10000000
	beq .not_8501
	lda $01
	and #%00100000
	bne .not_8501		; 8501 bit5 stuck 0
	lda #0
	sta cpu_port_type
	jmp .restore
.not_8501:
	; 6510: bits 7-6 clear, idle CLK-in on bit 5 high
	lda $01
	and #%11000000
	bne .unknown
	lda $01
	and #%00100000
	beq .unknown
	lda #1
	sta cpu_port_type
	lda KERNAL_CPU_DIR_INIT
	cmp #%00001111
	bne .restore		; patched → type 1
	inc cpu_port_type	; type 2
	jmp .restore
.unknown:
	lda #3
	sta cpu_port_type
.restore:
	pla
	sta $01
	rts
```

If the 8501 follow-test is too strict in VICE, prefer matching [siziolib `detect/detect.inc`](https://github.com/iszell/siziolib/blob/master/detect/detect.inc) `detect_cpu_port_type` byte-for-byte once cloned; VICE xplus4 must remain type 0.
