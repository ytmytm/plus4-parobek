# fast1541iec Stock 1541 Serial Fastloader Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a ROM-safe serial IEC fast LOAD for stock 1541-class drives (no parallel cable), falling back to ROM when detect/upload/transfer fails.

**Architecture:** Research MegaLoad V4 first; if reverse-engineering fails or uses ATN-as-data, implement a 2-bit CLK/DATA protocol reusing the Plus/4 SJL host receive style with uploaded 1541 drivecode. Gate after burst → SJL(SD2IEC) → parallel → SJL(JD), only when `par1541_detect` reported “1541 but no parallel” (`A=$80`).

**Tech Stack:** ACME 6502, GNU make, VICE `xplus4`, existing Parobek `load_status` / `iec_load` patterns; references: MegaLoad, [siziolib](https://github.com/iszell/siziolib), Open ROMs JiffyDOS notes, pagetable 2-bit protocol.

## Global Constraints

- File prefix: `fast1541iec` (detect / loader / highcode / drivecode).
- CLK/DATA only for fast transfer; ATN only for normal IEC commands. No ATN-as-data.
- Stock 1541 only; JD/SD2IEC stay on SJL; parallel stays on SpeedDOS.
- `iec_load` order: burst → SD2IEC+SJL → parallel → drive-JD+SJL → **fast1541iec** → ROM.
- Gate: only if `par1541_detect` returned `$80` (1541, no parallel interface bits). Reuse siziolib / `par1541` `M-R` ideas; no `UI` for detection.
- Protocol: spike MegaLoad first; if RE fails → 2-bit (SJL host + new drive sender); last resort → siziolib 1-bit handshake.
- No self-mod in shipped ROM path; `load_status` `$80` / `$00` / error (no double-load).
- Datasette: reuse `datasette_blocks_sjl` (same `$00`/`$01` conflict) before bitbang.
- Do not leave sticky drivecode across loads unless spike proves bus-safe.
- Stay under `$C000` executable guard. Branch: `feature-fast1541iec`. Spec: `docs/superpowers/specs/2026-08-25-fast1541iec-design.md`.

- [ ] **Step 2: Record candidate in `.try_parallel`**

Replace the start of `.try_parallel` so the detect result is classified before the parallel-vs-JD branch:

```asm
.try_parallel:
	lda #0
	sta fast1541iec_candidate
	jsr par1541_detect
	sta $d0
	cmp #$80
	bne .par1541_check_cable
	lda #1
	sta fast1541iec_candidate	; 1541, no parallel bits
.par1541_check_cable:
	bit $d0
	bpl .try_drive_jd
	and #%01111111
	beq .try_drive_jd
	lda #<iec_parallel_txt
	ldy #>iec_parallel_txt
	jsr print_msg
	lda $d0
	jmp SpeedDOS_load
```

- [ ] **Step 3: Call stub before ROM**

```asm
.try_drive_jd:

	lda iec_drive_flags
	and #%00000010
	beq .try_fast1541iec
	jsr datasette_blocks_sjl
```

- [ ] **Step 2: Wrapper uploads and jumps to highcode**

In `fast1541iec-loader.asm`, replace the stub body with SpeedDOS-like flow:

```asm
fast1541iec_load:
	!zone fast1541iec_Loader {
		lda #<fast1541iec_txt
		ldy #>fast1541iec_txt
		jsr print_msg

		jsr shared_rom_check
		bcs .fail

		; M-W fast1541iec_drivecode .. end → $0300
		; M-E $0300 (or $0303)
		; On any error → .fail

		lda TED_BORDER
		sta RAM_TED_BORDER_BACKUP
		lda TED_FF06
		sta RAM_TED_FF06_BACKUP
		and #$ef
		sta TED_FF06
		lda TED_FF13
		sta RAM_TED_FF13_BACKUP
		ora #%00000010
		sta TED_FF13

		jmp fast1541iec_highcode

.fail:		lda #$80
		sta load_status
		rts

fast1541iec_txt:
		!text "1541 SERIAL",13,0
	}
```

Copy the exact `M-W` chunk sender from `speeddos-loader.asm` (same listen SA `$6F`, 32-byte chunks) rather than inventing a new command builder. Point payload at `fast1541iec_drivecode` / `fast1541iec_drivecode_end`.
